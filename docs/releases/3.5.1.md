# Structure Timers 3.5.1 — SDE compatibility

- Accept `django-eveonline-sde>=0.2.0,<=2.0.0`, preserving installations on
  0.2.0 and allowing the 2.0.0 release.
- Test both SDE versions on Python 3.10–3.12 with Auth 5 / Django 5.2,
  including compatibility with the independent AA StratCom app.
- Exercise the actual JSONL loader before checking geography, gate links,
  ship searches and pasted D-scan classification.

## Upgrade

Keep the SDE version chosen for the complete Auth installation pinned in its
deployment constraints. Installing this release does not require changing 0.2.0.
If selecting 2.0.0, install its required dependencies too; `--no-deps` alone
does not provide the newer modeltranslation, httpx2 and brotli requirements.
SDE 2.0.0 requires Python 3.10–3.14 and Django 5.2 or later; this app continues
to target Auth 5 / Django 5.2.

Back up the complete database, environment and configuration, and stop web,
Celery worker and Beat processes before upgrading SDE. Keep `modeltranslation`
first in `INSTALLED_APPS`, with `eve_sde`, `aa_stratcom` and the separate
`structuretimers` app each enabled once when used. After installing the reviewed
package versions, run:

```sh
python manage.py migrate --plan
python manage.py migrate
python manage.py esde_load_sde --plan
python manage.py esde_load_sde
python manage.py check
python -m pip check
```

`--plan` is an SDE 2.0.0 option. Its first REST import reloads every model once.
Review the SDE admin import status, maps, gate links, ship lookup and D-scan
before restarting services. Set the SDE update check to run hourly:

```python
CELERYBEAT_SCHEDULE["EVE SDE :: Check for SDE Updates"] = {
    "task": "eve_sde.tasks.check_for_sde_updates",
    "schedule": crontab(minute="30"),
}
```

This maintenance release adds no Structure Timers migrations relative to its
base, pre-rename commit dd3a34aa1d164c67c7bd226428c6698559685fc4. It retains
the independent structuretimers app. The fork reused version 3.5.0 across
multiple commits: confirm the installed source commit and review all pending
application migrations if upgrading an earlier snapshot. No legacy-to-StratCom
data copy is required. AA StratCom needs its own compatible distribution,
such as version 4.1.6.
Other installed apps must independently permit the selected SDE version.

SDE migrations 0037–0040 are required when moving from its 0.2.0 schema.
Migration 0038 removes duplicate relation rows and its reverse operation cannot
restore them. Roll back a failed deployment using the matched database,
environment and configuration backups together.

See the [upstream 2.0.0 release](https://github.com/Solar-Helix-Independent-Transport/django-eveonline-sde/releases/tag/2.0.0)
and [setup documentation](https://github.com/Solar-Helix-Independent-Transport/django-eveonline-sde/blob/2.0.0/README.md).
